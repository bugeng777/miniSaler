## 二、技能系统跨组协作矩阵（重点）

22 个技能中，多数需要 3 组配合。这是 Phase 3 最复杂的跨组任务，必须明确分工：

| 技能类别 | WS2（效果逻辑） | WS3（资金/持仓） | WS1（市场钩子） | WS5（UI显示） |
|---|---|---|---|---|
| 分析类（5） | 计算触发条件 | — | 提供内在价值/大户数据 | 显示信号/指标 |
| 执行类（5） | 冷却/批量逻辑 | 修改订单执行 | 提供快速下单钩子 | 显示止损线/标记 |
| 防御类（5） | 效果判定 | 爆仓保留/利息计算 | — | 显示预警/延长条 |
| 社交类（4） | 假消息/跟随逻辑 | — | — | 显示他人方向 |
| 激进类（3） | 倍率/限制逻辑 | 修改资金上限/持仓限制 | — | 显示杠杆状态 |

**契约先行原则**: WS2 先定义每个技能的 `SkillEffect` 数据结构和触发信号，CTO 冻结后 WS1/WS3/WS5 才开始实现各自部分。

## 四、跨组依赖关系

```
[技能系统链]
WS2 定义 SkillEffect 契约 (Week 1)
   │
   ├──► WS1 实现市场钩子（内在价值/大户数据/快速下单）
   ├──► WS3 实现资金修改（杠杆/利息/爆仓保留）
   └──► WS5 实现技能 UI（信号/指标/预警显示）

[Boss 系统链]
WS2 Boss 击败判定 (Week 3)
   │
   ├──► WS1 Boss 价格操纵行为
   ├──► WS4 Boss 事件广播
   └──► WS5 Boss 过场动画 + 音效

[排行榜链]
WS3 leaderboard_manager (Week 5)
   │
   ├──► WS4 排行榜数据网络同步
   └──► WS5 leaderboard_screen UI

[匹配系统链]
WS4 matchmaking (Week 5) ── 独立，仅依赖 WS3 段位数据（已有）

[产品打磨链]
WS5 视觉特效/氛围/新手引导 (Week 7) ── 完全独立
```

## 五、里程碑与阻塞点

| 周次 | 里程碑 | 关键阻塞点 |
|---|---|---|
| **Week 1-2** | 技能完整实现 | WS2 契约必须第一天冻结，否则 WS1/WS3/WS5 全阻塞 |
| **Week 3-4** | Boss + 成就完整 | WS2 Boss 判定 → WS1/WS4/WS5 依赖 |
| **Week 5-6** | 多人匹配可用 | WS4 匹配 + WS3 排行榜并行 |
| **Week 7-8** | 视觉打磨 + 新手引导 | WS5 独立收尾，其他组转 code review |

## 六、Phase 3 与 Phase 2 的差异

| 维度 | Phase 2 | Phase 3 |
|---|---|---|
| 主要工作 | 修 bug + 骨架填充 | 内容深度 + 联机 + 打磨 |
| 跨组复杂度 | 低（信号契约简单） | **高**（技能系统 4 组协作） |
| 新增文件 | 0（都在已有文件内） | ~7 个新文件 |
| 风险点 | 单组滞后（如 WS2） | 技能契约不冻结导致返工 |

**Phase 2 复盘教训应用**: 首日强制冻结技能契约，避免 WS2 再次成为瓶颈。
